# Manzil — إدارة العمارة

تطبيق ويب عربي (RTL) لإدارة الشقق والاشتراكات والتحصيلات والمصروفات والصناديق والتقارير، مع بوابة مالك للقراءة فقط. يعمل كـPWA ويستخدم Supabase للمصادقة وPostgreSQL، وRLS لعزل بيانات كل مبنى.

الإصدار الحي: **manzil-v142** (`sw.js` → `CACHE_NAME`، `js/telemetry.js` → `RELEASE`).

## التشغيل

```sh
npm install          # مرة واحدة
npm run build:index  # يبني index.html من src/
npx serve .          # أو أي خادم ثابت محلي
```

`index.html` **ملف مولَّد**: لا يُحرَّر يدويًا. القالب في `src/index.template.html` والأقسام في `src/partials/`. بعد أي تعديل على القوالب:

```sh
npm run build:index
npm run check:index   # يفشل إن كان index.html غير محدَّث
```

النشر عبر GitHub Pages من فرع `main`، بلا خادم بناء ولا خطوة نشر يدوية.

## الميزات

- **التحصيل:** غرض لكل تحصيل (اشتراك/تطوير/طارئ/أخرى)، صندوق مستلم، دفعة مختلطة بعدة بنود بمجموع مُتحقَّق، توزيع على الأشهر، وسداد متأخرات ودفعات مقدمة.
- **الإيصالات:** إيصال موحّد للدفعة أو البند، طباعة A5 وPDF.
- **الاشتراكات:** سعر افتراضي للعمارة + سعر لكل شقة بتاريخ سريان شهري، ورقة أسعار شهرية للمدير، وبداية محاسبة قابلة للتعديل.
- **التسويات:** إعفاء/تخفيض/تسوية شهرية بسبب إلزامي، تُخصم من المستحق بلا حركة نقدية وتظهر في كل الكشوف والتقارير.
- **الصناديق:** الخزنة الرئيسية + التطوير + الطوارئ، أرصدة محسوبة، تحويلات داخلية موثقة لا تُحسب إيرادًا أو مصروفًا، وإقفال شهري مع مطابقة.
- **المصروفات:** ربط بصندوق وتصنيف، معاينة الرصيد قبل/بعد، ومنع تجاوز الرصيد.
- **التقارير:** تقرير المالك، تقرير الفترة، تقرير المصروفات، تقرير الإعفاءات والتخفيضات، وكشف حساب الشقة — بفلاتر شهر/غرض/صندوق/طريقة دفع/شقة، وتصدير CSV وPDF وطباعة.
- **المساعد المحلي:** «عم عبده البواب» متاح للمدير وللمالك، وكل ردوده تُحسب من بيانات الجلسة على الجهاز بلا أي اتصال شبكي. ينادي كل مستخدم باسمه (اسم الساكن للمالك، واسم الحساب في الملف الشخصي للمدير)، ويذكر آخر فترة وآخر شقة في نفس الجلسة فتكفي متابعة مثل «هو دفع كام؟»، ويعرض تحت كل رد ثلاثة أسئلة متابعة باسم الشهر الذي يُقصد، والمحادثة تبقى مفتوحة لو أُغلق المودال أو حُدّثت الصفحة — ومحفوظة لكل هوية على حدة فلا يستعيد المالك محادثة المدير في نفس التبويب. للمالك أسئلة تخص شقته فقط (حسابي، إيصالاتي، ميعاد الدفع والمهلة، طرق الدفع المفعّلة، إشعاراتي، إعفاءاتي)، أما أسئلة العمارة كاملة («رصيد الخزنة كام؟»، «تقرير المالك») فيُرد عليها بأنده تخص الإدارة مع قائمة بما يقدر يسأل عليه. الزر العائم يبقى ظاهرًا في بوابة المالك: ينكمش إلى دائرة عند النزول ويتوسّع عند الصعود.
- **بوابة المالك:** رصيد الوحدة، دفعاتها، إعلانات المبنى، وبيانات الدفع المفعّلة — قراءة فقط. ومظهر البوابة يُختار من زر واحد في الهيدر يفتح قائمة الثيمات الستة ويُحفظ لحساب المالك وحده.
- **الواجهة:** RTL، ثيمات متعددة، تخطيط متجاوب، وإمكانية وصول أساسية (ARIA، أهداف لمس، لوحة مفاتيح). أفاتار «عم عبده» صورة PNG شفافة مستخرجة من رسم واحد بخلفية شفافة، تُستخدم في الزر العائم ورأس المودال وصورة الترحيب، ومقصوص بنافذة تبدأ فوق العمامة فلا تُقصّ مع أي ثيم. رأس المودال يكتفي بسطر واحد: «بيانات التطبيق فقط».

## النسخ الاحتياطي والاستعادة

- نسخة PostgreSQL يومية تلقائية الساعة 02:23 UTC عبر GitHub Actions، بصيغة مضغوطة مع SHA-256 وفحص أرشيف قبل الرفع.
- تُرفع `.dump` و`.sha256` إلى مستودع GitHub خاص منفصل `manzilsystem/manzil_backups`، ويُحتفظ بآخر **30 نسخة**.
- كل نسخة مسجلة في `backup_catalog`، مع مزامنة Releases ومهلة أمان 24 ساعة قبل تنظيف العناصر اليتيمة.
- من «الإعدادات ← النسخ الاحتياطي»: عرض النسخ، طلب نسخة يدوية، تنزيل النسخة (عبر `backup-console` Edge Function التي تحتفظ بـ`BACKUP_REPO_TOKEN` بعيدًا عن المتصفح)، ومتابعة الحالة.
- طلب الاستعادة يتطلب مديرًا يدير جميع المباني، ونافذة منفصلة بكتابة `RESTORE`. العامل يتحقق من SHA-256 المطابق للكتالوج قبل التنفيذ.
- **الاستعادة تستبدل قاعدة الإنتاج بالكامل** بما فيها جميع المباني والحسابات. لا تُجرَّب على الإنتاج. اختبار الاستعادة المعزول نُفِّذ بنجاح على مشروع مؤقت في 2026-11-05 ثم حُذف.
- تصدير/استيراد JSON مسار منفصل لبيانات العمارة فقط، ولا يستبدل قاعدة البيانات.
- النسخ **ليست مشفرة**؛ الحماية تعتمد على خصوصية المستودع وصلاحيات GitHub/Supabase.

## الدخول

- **المدير:** بريد إلكتروني وكلمة مرور.
- **المالك:** رقم هاتف الشقة وPIN. رمز مؤقت من 8 أرقام عند أول دخول، يُغيَّر إلى PIN دائم من 6 أرقام.
- RLS يحدد نطاق الوصول عبر `building_members`، وبوابة المالك للقراءة فقط.
- الجلسة تُقفل تلقائيًا بعد 5 دقائق بلا نشاط، وتُمسح بياناتها عند القفل أو تسجيل الخروج.

## التحديثات

`sw.js` يعمل بنمط الشبكة أولًا مع `updateViaCache: 'none'`، فيصل كل إصدار عند إعادة الفتح دون مسح كاش. إذا كانت هناك نافذة أو حقل قيد الإدخال، يُؤجَّل التحديث ويُعاد المحاولة دوريًا وعند العودة للتطبيق. لا تُمسح بيانات الجلسة أو المدخلات أثناء التحديث.

## حدود حالية

- الخدمات المجانية فقط: لا Supabase paid branches ولا خدمات مراقبة مدفوعة.
- Leaked Password Protection غير متاحة في الخطة الحالية؛ لا تُغيَّر سياسة PIN أو المصادقة لتجاوز التحذير.
- لا API واتساب: الرسائل تُفتح عبر روابط `wa.me` بيد المستخدم.
- لا تستخدم `service_role` في المتصفح ولا تضع أي سر في الواجهة أو المستودع أو السجلات.
