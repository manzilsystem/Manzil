# Manzil — إدارة العمارة

واجهة عربية باتجاه RTL لإدارة الشقق والاشتراكات والتحصيلات والمصروفات والإعلانات والتقارير الشهرية. تستخدم Supabase Auth للمصادقة وRLS لعزل بيانات الملاك، وتتضمن بوابة مالك للقراءة فقط وواجهة إدارة.

## التشغيل

افتح `index.html` عبر استضافة ثابتة تدعم HTTPS أو خادم محلي. يحتاج التطبيق إلى اتصال بـ Supabase Auth وقاعدة البيانات. لا يعتمد حفظ سجلات التطبيق على `localStorage` أو GitHub Gist.

## الاختبارات

شغّل الاختبارات كاملة باستخدام Node.js:

```sh
node --test tests/*.test.cjs
```

تشمل المجموعة اختبارات الحالة، المصادقة والجلسات، الصلاحيات، التقارير، الحفظ الذري، إعدادات الواجهة، والنسخ الاحتياطي والاستعادة. تعمل GitHub Actions تلقائيًا على Pull Requests وتحديثات `main`، وتشمل اختبارات Node وتكامل PostgreSQL.

## البيانات والنسخ الاحتياطي والاستعادة

- بيانات التشغيل الأساسية محفوظة في Supabase، مع تفعيل RLS وسياسات عزل بيانات المباني والملاك.
- تُنشأ نسخة PostgreSQL تلقائية يوميًا الساعة 02:23 UTC (04:23 بتوقيت مصر).
- يستخدم مسار النسخ `pg_dump` بصيغة PostgreSQL المضغوطة، ويحسب SHA-256 ويتحقق منه ويفحص بنية الأرشيف قبل رفعه.
- تُرفع ملفات `.dump` و`.sha256` إلى مستودع GitHub خاص منفصل، ويُحتفظ بآخر 30 نسخة.
- يُسجل كل Backup في `backup_catalog`. تتم مزامنة السجل مع ملفات Releases، مع مهلة أمان 24 ساعة قبل تنظيف العناصر اليتيمة أو السجلات التي لم يعد لها Release.
- من الإعدادات ← النسخ الاحتياطي يستطيع المدير عرض النسخ وطلب نسخة يدوية ومتابعة حالتها.
- طلب الاستعادة متاح للمدير من داخل التطبيق. يتحقق Supabase Edge Function من الجلسة والصلاحية والنسخة المختارة، ثم ينفذ GitHub Actions العامل الطلب كل خمس دقائق بعد التحقق من SHA-256 ومطابقة القيمة الموثوقة في الكتالوج وصلاحية أرشيف PostgreSQL.
- **الاستعادة تستبدل قاعدة بيانات الإنتاج بالكامل**، بما يشمل بيانات جميع المباني والحسابات والسجلات. لا تبدأها إلا عند الضرورة وبعد التأكد من النسخة المختارة. بعد نجاح الاستعادة تُقفل جلسة المستخدم الذي بدأ الطلب ويُطلب منه تسجيل الدخول مجددًا.
- جداول التحكم في النسخ وطلبات الاستعادة مستثناة من النسخ حتى تظل متاحة لتشغيل مسار الاستعادة.
- تصدير/استيراد JSON وظيفة منفصلة لبيانات التطبيق، وليس بديلًا عن نسخة PostgreSQL الكاملة.
- النسخ الحالية ليست موصوفة بأنها مشفرة؛ الحماية تعتمد على خصوصية مستودع النسخ، وصلاحيات GitHub/Supabase، والتحقق من سلامة الملفات. لا تُخزن مفاتيح أو كلمات مرور في الواجهة أو المستودع.

## دخول المدير والملاك

- يدخل المدير بالبريد الإلكتروني وكلمة المرور. يدخل المالك برقم الهاتف المسجل للشقة وPIN؛ الرمز المؤقت من 8 أرقام ويجب تغييره عند أول دخول إلى PIN دائم من 6 أرقام.
- يحدد `building_members` الدور، وتفرض RLS حدود الوصول. بوابة المالك للقراءة فقط وتعرض بيانات وحدته ودفعاتها وإعلانات المبنى، ولا تسمح بإدارة بقية الشقق أو المصروفات.
- يربط المدير المالك بوحدته ويجهز PIN مؤقتًا ورسالة WhatsApp جاهزة يرسلها يدويًا.
- تُقفل الجلسة تلقائيًا بعد خمس دقائق بلا نشاط. عند القفل أو تسجيل الخروج تُمسح بيانات الجلسة وواجهة المستخدم السابق من الحالة والصفحة.
- لا تشارك حسابًا واحدًا بين الملاك. ملفات JSON المصدّرة قد تحتوي بيانات مالية، فاحفظها في مكان خاص.

## الوظائف

- إدارة بيانات الشقق والتحصيلات والمصروفات والإعلانات.
- لوحة مؤشرات وتدفق نقدي ومتابعة للمتأخرات والدفعات الجزئية.
- حفظ تاريخ قيمة الاشتراك وتاريخ سريانها لحساب الأشهر السابقة بالسعر التاريخي.
- تقارير شهرية قابلة للطباعة وتصدير CSV وJSON، وتقرير متأخرات مجمع مع تفاصيل الشهور.
- قوائم التحصيل والمصروفات والتقارير تدعم اختيار آخر 60 شهرًا مع الاحتفاظ بالأشهر الأقدم التي لها سجلات.
- ثيمات متعددة وتخطيط متجاوب باللغة العربية.

## حدود التشغيل الحالية

- المشروع يستهدف الخدمات المجانية فقط؛ لا يعتمد على Supabase paid branches أو خدمات مدفوعة.
- لم يُنفذ اختبار استعادة على قاعدة اختبار مستقلة؛ لا توجد بيئة Supabase اختبار منفصلة ضمن التشغيل الحالي. نجاح فحص الأرشيف وCI لا يُعد إثباتًا لاستعادة فعلية.
- حماية كلمات المرور المسرّبة في Supabase Auth غير متاحة ضمن خطة المشروع الحالية؛ لا تُغيّر إعدادات المصادقة أو سياسة PIN بهدف إزالة التحذير على حساب تعطيل دخول الملاك.
- لا تستخدم مفتاح `service_role` في المتصفح، ولا تشارك أسرار الاتصال أو رموز الوصول.
