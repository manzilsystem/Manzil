# Manzil — إدارة العمارة

واجهة عربية باتجاه RTL لمتابعة شقق العمارة والاشتراكات والتحصيلات والمصروفات والإعلانات والتقارير الشهرية. تستخدم Supabase Auth للمصادقة وRLS لعزل بيانات الملاك، وتتضمن بوابة مالك للقراءة فقط إلى جانب واجهة الإدارة.

## التشغيل

افتح `index.html` عبر استضافة ثابتة تدعم HTTPS أو خادم محلي. يحتاج التطبيق إلى اتصال بـ Supabase Auth وواجهة البيانات؛ لا يعتمد مسار التشغيل الحالي على `localStorage` أو GitHub Gist لحفظ سجلات التطبيق.

## الاختبارات

شغّل اختبارات حساب الدفعات والمتأخرات باستخدام Node.js المدمج دون تثبيت حزم: `node --test tests/state.test.cjs`.

## البيانات والنسخ الاحتياطي

- استخدم **النسخ الاحتياطي → تصدير JSON** عند الحاجة إلى نسخة خارجية، واحتفظ بها في مكان آمن.
- الاستيراد يستبدل البيانات الحالية بعد تأكيد صريح، ويتحقق من بنية الملف قبل الحفظ.
- التصدير إلى CSV مناسب لفتح السجلات في برامج الجداول. تظل النسخ مسؤولية المستخدم؛ حذف بيانات المتصفح أو فقدان الجهاز قد يؤدي إلى فقد النسخة المحلية.
- لا تُستخدم مزامنة GitHub Gist في مسار التشغيل الحالي؛ Supabase هو مصدر البيانات المركزي.
- المصادقة تتم عبر Supabase Auth، ولا تُخزّن كلمات المرور أو PINs داخل المتصفح.

## دخول المدير والملاك

- عند فتح التطبيق، يدخل المدير أو المالك بالبريد الإلكتروني وكلمة المرور عبر Supabase Auth. يحدد `building_members` الدور، وتفرض RLS حدود الوصول.
- يربط المدير حساب المالك بوحدته من خلال UUID حساب Supabase. بوابة المالك للعرض فقط وتعرض حساب شقته ودفعاتها وإعلانات العمارة؛ بينما تبقى الإدارة والتقارير والمصروفات وبقية الشقق للمدير.
- يمكن للمدير قفل الجلسة أو تبديل المستخدم من زر الخروج في الشريط العلوي.
- تُقفل الجلسة تلقائياً بعد خمس دقائق بلا نشاط، بما في ذلك عند ترك التطبيق في الخلفية لهذه المدة؛ النشاط في التطبيق يعيد تشغيل المؤقت.
- عند قفل الجلسة أو الانتقال من المالك إلى المدير، تُمسح واجهة بوابة المالك من الصفحة قبل عرض شاشة الدخول/لوحة الإدارة، فلا تبقى بيانات المالك السابق في DOM المخفي داخل الصفحة.

**تنبيه خصوصية مهم:** حماية البيانات تعتمد على Supabase Auth وسياسات RLS. لا تستخدم مفتاح `service_role` في الواجهة أو المستودع، ولا تشارك حسابًا واحدًا بين الملاك. ملفات JSON المصدّرة قد تحتوي بيانات مالية، لذلك يجب حفظها خارج الأماكن العامة.

## ملاحظات على الأتمتة

الملف `auto_backup.yml` الموجود في جذر المستودع ليس مسار GitHub Actions فعّالاً، كما أنه يبحث عن `manzil_data.json` بينما يخزن التطبيق السجلات في `localStorage` أو في Gist اختياري. لذلك لا تنفّذ هذه الأتمتة نسخاً احتياطية من بيانات المستخدم. لا يُنصح بنقلها إلى `.github/workflows/` قبل تصميم مسار آمن ومصرّح به لجلب بيانات Gist وتخزينها.

## الوظائف

- يتضمن التطبيق دليل استخدام عربيًا يشرح إعداد العمارة، إضافة الشقق، تسجيل التحصيلات والمصروفات، ومراجعة التقارير والنسخ الاحتياطي.
- لوحة مؤشرات، متابعة المتأخرات بما فيها الدفعات الجزئية، وعرض التدفق النقدي. تُخصم كل دفعة من مستحق الشهر نفسه، لكن التطبيق لا يحتفظ بتاريخ تغيّر قيمة الاشتراك؛ لذلك تُحسب الأشهر السابقة بسعر الاشتراك الحالي للشقة.
- تقرير متأخرات مجمع يعرض إجمالي المديونية، وعدد الشقق والأشهر غير المسددة، ويصنف الحالات إلى شهر واحد، و2–3 أشهر، و4 أشهر فأكثر، مع تفاصيل الشهور وتصدير CSV مستقل.
- تتيح قوائم التحصيل والمصروفات والتقارير اختيار آخر 60 شهرًا حتى يمكن تسجيل الحركات المتأخرة، مع الإبقاء على الأشهر الأقدم التي توجد لها سجلات.
- إدارة بيانات الشقق والتحصيلات والمصروفات والإعلانات.
- بوابة مالك برمز خاص، للقراءة فقط، تعرض حساب الشقة نفسها دون كشف سجلات الشقق الأخرى في الواجهة.
- تقارير شهرية قابلة للطباعة وتصدير CSV وJSON.
- ثيمات داكنة وفاتحة وزمردية، مع تخطيط متجاوب بالعربية.

## أولويات التطوير المقترحة

1. حفظ سجل تاريخي لقيمة الاشتراك وتاريخ سريان كل تغيير، لأن حساب الأشهر القديمة يستخدم حالياً قيمة الاشتراك الحالية.
2. إنشاء نسخ احتياطية مجدولة ومشفرة مع تجربة استعادة واضحة.
3. بعد استقرار الصلاحيات: تحسين سجل التدقيق والإشعارات وتقارير الإقفال الشهري.

## مسار Supabase

أضيفت migrations لإنشاء مخطط Supabase وتفعيل RLS في `supabase/migrations/`، مع دليل تهيئة أول مدير واختبارات الخصوصية في [`docs/supabase-rollout.md`](docs/supabase-rollout.md). الواجهة الحالية تستخدم Supabase Auth والجداول الجديدة؛ يجب تهيئة أول مدير وربط حسابات الملاك قبل الاستخدام الفعلي.
