# Manzil — إدارة العمارة

واجهة عربية لإدارة الشقق والتحصيلات والمصروفات والإعلانات والتقارير. GitHub يحفظ الشيفرة وملفات النشر؛ Supabase يوفر تسجيل الدخول وقاعدة البيانات وسياسات Row Level Security (RLS). GitHub Pages وحده لا يفرض سرية بين الملاك.

## الأدوار والدخول

شاشة الدخول تفصل بين **الإدارة** و**الملاك**. الإدارة تدخل ببريد وكلمة مرور Supabase Auth، ودورها المخزن في `public.profiles.role` هو `admin`. المالك يدخل برقم الهاتف وPIN من 8 أرقام، ويرتبط حسابه بمعرّف شقته في `profiles.apartment_id`. الدور `owner` للقراءة فقط، وسياسات RLS تسمح له بقراءة بيانات شقته ودفعاتها والإعلانات المنشورة؛ الإدارة وحدها تدير بيانات العمارة.

PIN كلمة مرور لدى Supabase Auth، وتخزنها خدمة المصادقة كقيمة مجزأة. لا تُخزن PIN كنص واضح في جدول عام. أداة المدير تنشئ حساب المالك عبر Supabase Edge Function محمية، ثم تعرض رابط WhatsApp بنص جاهز. لا تستخدم WhatsApp API ولا ترسل الرسالة تلقائيًا؛ المدير يراجعها ويرسلها بنفسه.

**أمان التسجيل:** لا يوجد تسجيل ذاتي يعتمد على رقم الشقة والهاتف فقط؛ فهذان الرقمان لا يثبتان هوية صاحبهما. يتحقق المدير من الهاتف، ثم ينشئ الحساب ويرسل PIN للمالك. تفاصيل الإعداد والأكواد والنشر في [دليل إعداد دخول المالك وPIN وWhatsApp](docs/owner-pin-onboarding-ar.md).

## إعداد Supabase باختصار

1. أنشئ مشروعًا وشغّل `supabase/migrations/20261101163000_secure_owner_manager_access.sql` في SQL Editor.
2. أنشئ مستخدم الإدارة الأول في Authentication ثم اربطه بصف `profiles` بدور `admin`، وفق SQL الموجود بالدليل.
3. ضع Project URL وpublishable key فقط في `js/supabase-config.js`.
4. انشر وظيفة إنشاء حساب المالك: `supabase functions deploy provision-owner` بعد `supabase login` و`supabase link`. لا تضع مفتاح الخدمة في الواجهة أو GitHub.
5. اختبر سياسات RLS والوظيفة على مشروع تجريبي، ثم ادفع التغييرات عبر GitHub وانشر الواجهة الثابتة.

إعداد `js/supabase-config.js` فارغ عمدًا حتى يربطه مالك المشروع بمشروعه. قبل ذلك يظهر وضع التوافق المحلي القديم مع تحذير أن PIN المحلي ليس عزلًا أمنيًا. لا تدخل بيانات حقيقية أو تشارك نسخة البيانات في هذا الوضع.

## البيانات والنسخ الاحتياطي

- تصدير JSON/CSV متاح للإدارة؛ احتفظ بالنسخ خارج المستودع وفي مكان آمن.
- الاستيراد يستبدل البيانات الحالية بعد تأكيد صريح، ويرفعها إلى Supabase عند اتصال المشروع.
- لا تستخدم GitHub Gist أو مستودع GitHub لحفظ سجلات السكان أو ملفات PIN.
- جلسات Supabase تقفل تلقائيًا بعد خمس دقائق من عدم النشاط.

## الوظائف

- لوحة مؤشرات، إدارة الشقق والتحصيلات والمصروفات والإعلانات، وتقارير شهرية ومتأخرات.
- بوابة مالك للقراءة فقط تعرض الشقة المرتبطة بحسابه ودفعاتها وإعلانات العمارة المنشورة.
- حفظ مركزي في Supabase، مع RLS على مستوى الصفوف وصلاحيات إدارة حصرية لـ`admin`.
- قوالب عربية RTL وتخطيط متجاوب، وتصدير تقارير ونسخ احتياطية.

## الفحوص المحلية

```bash
for f in js/*.js sw.js; do node --check "$f"; done
python3 scripts/check_security_contract.py
```

لا تعدّل سياسات RLS أو تضف جداول بيانات جديدة دون اختبار مباشر بحساب admin ومالكين مختلفين، والتحقق من أن محاولة الوصول إلى بيانات شقة أخرى مرفوضة من Postgres نفسه.
