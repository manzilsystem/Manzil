# دليل الدخول وإصدار PIN للمالك عبر Supabase وWhatsApp

هذا الدليل يشرح التدفق الموجود في هذا الفرع. GitHub يحتفظ بالشيفرة، وSupabase Auth/Database يطبّق المصادقة والخصوصية. لا توجد خدمة SMS أو WhatsApp API مدفوعة: زر WhatsApp يفتح المحادثة بنص مجهز، ويضغط المدير **إرسال** يدويًا.

## نقطة أمان مهمة قبل البدء

إدخال رقم الشقة ورقم الهاتف وحدهما لا يثبت أن من يكتب البيانات هو المالك؛ يمكن لشخص آخر معرفة الرقمين وحجز الحساب قبله. لذلك لا يوجد تسجيل ذاتي مفتوح يولد PIN للزائر. المسار الآمن والبسيط هو أن يتحقق المدير من رقم المالك مرة واحدة، ثم ينشئ الحساب له من داخل التطبيق. المالك بعد ذلك يدخل برقم هاتفه وPIN فقط.

لا نحفظ PIN كنص واضح في جدول عام. ينشئه الخادم الموثوق كرمز عشوائي من 8 أرقام، ويمرره إلى Supabase Auth ككلمة مرور؛ Supabase يخزن كلمة المرور بهش salted hash في مخزن المصادقة المحمي. جدول `public.profiles` يحفظ الهاتف والدور وربط الشقة، ولا يحتوي نسخة مكشوفة من الرمز. لا تضع `service_role` في GitHub أو JavaScript أو المتصفح.

## الحقول والأدوار

| المكان | الحقول | الغرض |
|---|---|---|
| `auth.users` في Supabase | الهاتف، بيانات المصادقة/كلمة المرور المجزأة | دخول المالك برقم الهاتف والـPIN؛ ودخول الإدارة بالبريد وكلمة المرور |
| `public.profiles` | `id`, `building_id`, `role` (`admin` أو `owner`), `apartment_id`, `phone`, `display_name` | ربط الحساب بالعمارة والشقة وتطبيق سياسات RLS |
| `public.apartments` | `id`, `building_id`, `data` ويحتوي `apartmentNumber` | رقم الشقة وتفاصيلها. `profiles.apartment_id` يشير إلى سجل الشقة |

كلمة PIN هي كلمة مرور Supabase Auth، وليست حقل نص في `profiles`. هذا التصميم يمنع استخراج رموز الملاك من استعلام جدول عام أو من نسخة احتياطية للتطبيق.

## الخطوة 1: إنشاء مشروع Supabase وقاعدة البيانات

1. أنشئ مشروع Supabase.
2. افتح **SQL Editor** وشغّل كامل الملف `supabase/migrations/20261101163000_secure_owner_manager_access.sql`.
3. من **Authentication → Providers** فعّل Email/Password وPhone/Password، وأوقف التسجيل العام غير المصرح به. لا يلزم إعداد مزود SMS لأن المدير يثبت رقم الهاتف عند إنشاء الحساب بـ`phone_confirm: true`.
4. تأكد من عدم وجود سياسة RLS أخرى أوسع من سياسات migration. كل الجداول الحساسة يجب أن تظل محمية بـRLS.

## الخطوة 2: إنشاء حساب الإدارة الأول

أنشئ حساب مدير بالبريد وكلمة مرور قوية من **Authentication → Users**. بعد الإنشاء، نفّذ SQL التالي مع استبدال البريد والاسم:

```sql
insert into public.profiles (id, building_id, role, display_name)
select id, 'main', 'admin', 'مدير العمارة'
from auth.users
where lower(email) = lower('admin@example.com')
on conflict (id) do update
set building_id = excluded.building_id,
    role = 'admin',
    apartment_id = null,
    display_name = excluded.display_name;
```

دخول الإدارة في الشاشة المنفصلة يستخدم البريد وكلمة مرور Supabase Auth؛ لا يستخدم PIN المالك.

## الخطوة 3: ضبط التطبيق على المشروع

عدّل `js/supabase-config.js` بالقيمتين العامتين من **Project Settings → API**:

```js
window.MANZIL_SUPABASE_CONFIG = Object.freeze({
  url: 'https://YOUR-PROJECT-REF.supabase.co',
  publishableKey: 'sb_publishable_...'
});
```

`url` و`publishableKey` متوقع ظهورهما في المتصفح. لا تستخدم `service_role` أو مفتاح `sb_secret_` هنا. إعداد ملف الواجهة ليس موضعًا للأسرار.

## الخطوة 4: نشر وظيفة إنشاء المالك

وظيفة Edge Function هي الجزء الخلفي الصغير الذي ينشئ مستخدم Auth بأمان. تتحقق من جلسة مستدعيها ومن أن صفه في `profiles` يحمل `role='admin'`، وتتحقق أن الشقة ضمن عمارة هذا المدير، ثم تولد PIN، وتنشئ المستخدم وتربطه بالشقة. لا يصل مفتاح الخدمة إلى المتصفح.

من مجلد نسخة الريبو، ثبّت Supabase CLI إن لم يكن موجودًا، ثم:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy provision-owner
```

توفر بيئة Supabase للوظيفة `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY` كمتغيرات تشغيل. لا ترفع قيمها في ملفات المشروع. الملف `supabase/config.toml` يشترط JWT صالحًا قبل تنفيذ الوظيفة.

## الخطوة 5: إنشاء حساب المالك وإرسال الرسالة

1. سجّل دخول المدير.
2. افتح **الإعدادات → إنشاء حساب مالك وإرسال PIN**.
3. اختر الشقة، وأدخل هاتف المالك بالصيغة الدولية E.164، مثل `+201xxxxxxxxx`. تأكد من رقم الهاتف مع المالك قبل المتابعة.
4. اضغط **توليد PIN وحفظ الحساب**. تحفظ الوظيفة حساب الهاتف/الدور/الشقة وتضبط كلمة مرور Supabase Auth في العملية نفسها.
5. يظهر PIN للمدير ورابط **فتح واتساب بالرسالة الجاهزة**. اضغط الرابط، راجع اسم المستلم والنص ثم اضغط **إرسال** داخل WhatsApp. لا يحدث إرسال تلقائي؛ هذا قيد متعمد لعدم استخدام WhatsApp API.
6. إذا كان الرقم نفسه مربوطًا مسبقًا بالشقة نفسها، يعيد الزر تعيين PIN ويرجع الرمز الجديد للمدير. يرفض الرقم إذا كان مربوطًا بعمارة أو شقة أخرى.

لا ترسل PIN في مجموعة، ولا تصوره أو تتركه ظاهرًا على جهاز مشترك. من يحصل على الهاتف والـPIN يستطيع الدخول لذلك الحساب.

## الخطوة 6: دخول المالك

يفتح المالك التطبيق، يختار تبويب **الملاك**، ثم يدخل:

- رقم الهاتف نفسه الذي سجله المدير، بصيغة دولية `+...`.
- PIN المكون من 8 أرقام الذي وصل إليه عبر WhatsApp.

لا توجد شاشة تسجيل مفتوحة أو خيار يتيح للمالك اختيار شقة أخرى. `profiles.apartment_id` يحدد الشقة، وRLS في Postgres يقيّد قراءة الشقق والدفعات إلى سجل هذا المالك. المصروفات والإعدادات وسجل التدقيق تبقى للـadmin.

## التسليم عبر GitHub

بعد التحقق من إعداد المشروع التجريبي واختبار حساب admin وحسابين owner:

1. احفظ `js/supabase-config.js` بقيم Project URL وpublishable key فقط.
2. ادفع الفرع إلى GitHub وافتح PR إلى `main`.
3. ادمج PR بعد نجاح CI ومراجعة RLS.
4. انشر مجلد الموقع الثابت على GitHub Pages بالطريقة المعتمدة في المستودع. انشر Edge Function منفصلًا عبر أمر Supabase أعلاه.
5. لا ترفع ملفات JSON الحقيقية أو ملفات `.env` أو مفاتيح خدمة إلى أي فرع.

## اختبارات التسليم

- حساب admin يدخل من تبويب الإدارة؛ وحساب owner يدخل من تبويب الملاك. تبديل نوع الحساب لا يبدل الدور المحفوظ في قاعدة البيانات.
- أنشئ مالكين لشقتين مختلفتين. تأكد من أن كل واحد يرى حساب شقته فقط ودفعاتها والإعلانات المنشورة.
- تحقق من رفض محاولة owner قراءة المصروفات، أو تعديل البيانات، أو استدعاء `replace_building_state`، أو استدعاء `provision-owner`.
- أرسل PIN تجريبيًا عبر WhatsApp وتأكد من أن الرابط يجهز النص فقط ولا يدعي إرساله تلقائيًا.
- شغّل `supabase test db` إذا كانت حزمة Supabase المحلية متاحة؛ يحتوي `supabase/tests/owner_isolation.sql` اختبارات pgTAP.

## ما لا يمكن فعله دون قناة تحقق

لا يمكن بأمان السماح لأي شخص يكتب رقم الشقة والهاتف ليحصل على رمز دخول إلى هذا الرقم، ما لم توجد قناة تثبت امتلاكه للهاتف أو موافقة المدير. إرسال رسالة WhatsApp يحتاج ضغطًا يدويًا للحساب المُرسل، ولا يثبت تلقائيًا أن من طلب الرمز هو المالك. إذا كان شرط التسجيل الذاتي للمالك إلزاميًا، أضف دعوة لمرة واحدة يصدرها المدير أو تحقق OTP عبر مزود رسائل؛ لا تفتح التسجيل اعتمادًا على رقم الشقة والهاتف وحدهما.
